## フェーズ5: 取引・決済

*エスクロー = 購入者が支払った代金を第三者が預かり、発送確認後に出品者へ支払う安全な仕組み。*

- [ ] 購入後の商品ステータス更新（販売中→取引中）

*PAY.JPはカード番号をサーバーに送らない「トークン」方式を採用。これにより、カード情報漏洩リスクを最小化できる。*

### 5-3. 取引ステータス管理

- [ ] 取引キャンセル・返金フロー

## 付録: セキュリティ用語解説

| 用語 | 説明 |
|---|---|
| SQLインジェクション | 検索フォームなどに不正なSQL文を入力し、データベースを不正操作する攻撃 |
| XSS（クロスサイトスクリプティング）| 悪意あるJavaScriptを埋め込み、他のユーザーのブラウザで実行させる攻撃 |
| CSRF（クロスサイトリクエストフォージェリ）| 正規ユーザーに意図しない操作（送金・投稿等）を行わせる攻撃 |
| ブルートフォース攻撃 | パスワードを総当たりで試し続けてログインを突破する攻撃 |
| エスクロー | 代金を第三者が預かり、取引完了確認後に支払う仕組み |
| HTTPS | 通信を暗号化するプロトコル。HTTPSでない場合、通信内容が盗聴される可能性がある |
| 環境変数（.env）| APIキー・DB接続情報など秘密情報を、コードから切り離して管理する仕組み |
| マイグレーション | DBのテーブル設計変更をコードとして管理する仕組み（変更履歴として追跡可能） |
| レートリミット | 同一IPからの短時間のリクエスト回数を制限する仕組み |
